# Secrets, credentials and trust

> About the platform built from [mlqube/infrastructure](https://github.com/mlqube/infrastructure). Docs for all repositories live here, in `mlqube/.github` ([index](README.md)).

Every secret and trust relationship the platform depends on: where it lives, who uses it, when it expires and how to replace it. **This file never contains a secret value**, only names and locations.

Ground rules:

- No AWS access keys and no IAM users anywhere: people sign in through IAM Identity Center, CI through GitHub OIDC, pods through EKS Pod Identity.
- Secret values live only in **SSM Parameter Store** (SecureString) or **GitHub repository secrets**. Never in Git, workflow files, logs, tickets or chat. `gitleaks` runs in pre-commit and CI to catch mistakes.
- The platform is rebuilt from scratch each session, so most "rotation" is simply: update the stored value **before the next build**.

Never in Terraform state | You, [setup step 8](setup.md#8-router-auth-key) | **≤ 90 days** after creation |
| **`gitops` deploy key** (private half) | SSH key, ed25519 | SSM `/mlqube/argocd/gitops-deploy-key` (SecureString) | Terraform `addons-mgmt` → Kubernetes Secret `argocd/repo-gitops` → Argo CD repo server. **Also stored in the `addons-mgmt` Terraform state** (encrypted, private, versioned bucket) | You, [setup step 10](setup.md#10-argo-cd-deploy-key) | No expiry |
| **`gitops` deploy key** (public half) | Read-only deploy key `argocd-mgmt` | GitHub: `mlqube/gitops` → Settings → Deploy keys | GitHub, to authorize Argo CD's reads | You, setup step 10 | No expiry |
| **`TAILSCALE_CLIENT_ID`** | Client ID of the Tailscale trust credential | GitHub secret of `mlqube/infrastructure` | `terraform-layer.yml` → `tailscale/github-action` | You, [setup step 9](setup.md#9-ci-access-to-the-tailnet) | No expiry |
| **`TAILSCALE_CLAIM`** | **Audience** of the Tailscale trust credential | GitHub secret of `mlqube/infrastructure` | Same | You, setup step 9 | No expiry |
| **Argo CD SSO metadata** (not secret) | Identity Center sign-in URL and SAML certificate of the `Argo CD (MlQube)` application | SSM `/mlqube/argocd/sso-url`, `/mlqube/argocd/sso-ca`, `/mlqube/argocd/sso-admin-group-id` (String) | Terraform `addons-mgmt` → Dex's SAML connector | You, [setup step 10b](setup.md#10b-argo-cd-single-sign-on-iam-identity-center) | The certificate expires (Identity Center shows the date); replace both values when Identity Center rotates it |
| **Dex client secret for Argo CD** | Random 40-character secret | Secret `dex/dex-config` (Dex's client list) and Secret `argocd/argocd-dex-client`; also in the `addons-mgmt` Terraform state (encrypted, private bucket) | Dex and Argo CD, to trust each other | Terraform, on every build | Gone with each destroy; new one each build |
| **Argo CD initial admin password** (local admin **disabled**; break-glass only) | Random password, generated by Argo CD | Kubernetes Secret `argocd/argocd-initial-admin-secret` | You, to log in until single sign-on exists | Argo CD, on every build | Gone with each destroy; new one each build |

The two Tailscale values aren't keys by themselves: the trust credential only accepts a valid GitHub OIDC token from the right repository and branch. They're kept as secrets anyway, so they don't show up in logs.

**Platform secrets that pods need** (e.g. Grafana's admin password, later) go into **AWS Secrets Manager** under `mlqube/platform/<add-on>/<name>`, never into Git or this table's SSM parameters. The [External Secrets Operator](gitops/external-secrets.md) copies them into Kubernetes Secrets. Each one gets a row here when it is added.

| **EKS clusters** (access entries) | IAM roles | `mlqube-gha-apply` and the Identity Center **AdministratorAccess** role: cluster-admin. Needs no AWS permissions of its own | [argocd_clusters.tf](https://github.com/mlqube/infrastructure/blob/main/live/platform/addons/mgmt/argocd_clusters.tf) |
| **Add-on IAM roles** (Pod Identity) | Pods with a given service account | `kube-system/aws-load-balancer-controller`, `kube-system/external-dns`, `karpenter/karpenter`, `external-secrets/external-secrets` (read-only, Secrets Manager `mlqube/platform/*`), **one role each per cluster** (and the EBS CSI driver's) | [app_pod_identity.tf](https://github.com/mlqube/infrastructure/blob/main/live/platform/addons/mgmt/app_pod_identity.tf), [modules/eks-cluster](https://github.com/mlqube/infrastructure/blob/main/modules/eks-cluster/main.tf) |
| **Tailnet policy** | Devices with a tag | `tag:mlqube-router` may advertise and auto-approve `10.10.0.0/16`, `10.20.0.0/16`; `tag:ci` may join | Tailscale admin console, [setup step 7](setup.md#7-tailscale-tailnet) |

The immutable subject (`mlqube@<org-id>/…@<repo-id>`) means a deleted and re-created repository with the same name is **not** trusted by AWS or Tailscale until these subjects are updated.

## Your own credentials (laptop)

| Credential | Lifetime | Renew |
|---|---|---|
| AWS Identity Center session, profile `mlqube` | Some hours | `aws sso login --profile mlqube` |
| GitHub CLI login | Until revoked | `gh auth login` |
| Tailscale login | Until the device key expires (Tailscale default 180 days) | Tailscale app → log in again |
| kubeconfig contexts `mgmt`, `wl-nonprod` | No secret inside: `kubectl` calls `aws eks get-token` with your SSO session | Re-run `aws eks update-kubeconfig` after each rebuild (new endpoint) |

## Renewals calendar

| Item | Due | What happens if missed | Do |
|---|---|---|---|
| **Tailscale router auth key** | 90 days after it was generated. The parameter was last updated **2026-11-20**, so plan for about **2027-02-18**; the exact date is in Tailscale → Settings → Keys | The next build's router never joins the tailnet: no `kubectl`, and `addons-mgmt` fails with *"Can't reach the mgmt API through the tailnet"* | [Rotate it](#rotate-the-router-auth-key) a week before |
| **Domain `mlqube.click`** | **2027-11-19** (auto-renew off) | Domain lapses; certificate renewal and every name break | Route 53 → Registered domains → renew, or turn auto-renew on |
| ACM certificate | Renewed by ACM automatically | Only fails if the validation CNAMEs in the public zone are deleted | Keep the `base` layer applied |
| `gitops` deploy key | No expiry; replace yearly or if exposed | — | [Rotate it](#rotate-the-gitops-deploy-key) |

## Rotate the router auth key

1. Tailscale → **Settings → Keys → Generate auth key**: reusable, ephemeral, pre-approved, tag `tag:mlqube-router`, 90 days.
2. AWS console → **Parameter Store → `/mlqube/tailscale/router-authkey` → Edit** → paste the new value → Save.
3. The next platform build uses it. A router that is already running keeps working (the key is only used to join), so there's nothing to do mid-session.
4. Tailscale → Keys → **revoke** the old key.
5. Update the date in the [calendar](#renewals-calendar) above.

## Rotate the `gitops` deploy key

1. Create a new key pair and add it as a new read-only deploy key (setup step 10, a different `--title`).
2. Overwrite the parameter: `aws ssm put-parameter --name /mlqube/argocd/gitops-deploy-key --type SecureString --value file://argocd-gitops --overwrite --profile mlqube --region us-west-2`.
3. The next build (or `platform` → `addons-mgmt` → `apply` while running) puts the new key in the cluster.
4. Delete the old deploy key on GitHub (`gh repo deploy-key list --repo mlqube/gitops`, then `gh repo deploy-key delete <id> --repo mlqube/gitops`), and the local key files.

## Replace the Tailscale trust credential

Create a new credential (setup step 9), update both GitHub secrets with `gh secret set`, run `platform` → `addons-mgmt` → `plan` to check, then delete the old credential in Tailscale.

## If a secret leaks

| Leaked | Do immediately |
|---|---|
| Router auth key | Revoke it in Tailscale → Keys; check Machines for unknown devices and remove them; generate a new key ([rotate](#rotate-the-router-auth-key)) |
| `gitops` deploy key | Delete the deploy key on GitHub (it can only read `gitops`, which holds no secrets); create a new one ([rotate](#rotate-the-gitops-deploy-key)) |
| Tailscale trust credential values | Delete the credential in Tailscale; create a new one; update both GitHub secrets |
| Argo CD admin password | Usually nothing: the local admin is disabled. If it was enabled for a break-glass, set `argocd_admin_enabled = false` and apply, or destroy and rebuild |
| Anything in a Git commit | Treat it as leaked even after removing the commit: rotate it first, then clean up history |
