# Argo Workflows (workload clusters)

> Describes the code in [mlqube/gitops · `clusters/mgmt/argo-workflows/`](https://github.com/mlqube/gitops/tree/main/clusters/mgmt/argo-workflows) and [`platform/argo-workflows/`](https://github.com/mlqube/gitops/tree/main/platform/argo-workflows), and the Dex client in [mlqube/infrastructure · `sso.tf`](https://github.com/mlqube/infrastructure/blob/main/live/platform/addons/mgmt/sso.tf). Docs for all repositories live here, in `mlqube/.github` ([index](../README.md)).

> **Status:** 🕓 written (golden path v0, section 1); first test at the next build.

**Argo Workflows runs ML jobs and pipelines** as Kubernetes workflows: each step is a container, steps can depend on each other, fan out, retry. ML engineers write them in Python with **Hera** ([ADR-0005](../../adr/0005-argo-workflows-with-hera-for-ml-jobs.md)); in the golden path, the project's CI submits them on every push ([the golden path](../../golden-path.md)). Their step pods go through [Kueue](kueue.md), which decides when they start.

It runs on the **workload clusters** only, at **`https://workflows.nonprod.mlqube.click`** (over Tailscale).

## What exists, and who creates it

| What | Created by | Where |
|---|---|---|
| Workflow controller, Argo server (UI and API), CRDs; namespace `argo` | Argo CD, ApplicationSet `argo-workflows` (`<cluster>-argo-workflows`) | Workload clusters only (`mlqube/role: spoke`) |
| Ingress → internal ALB `mlqube-nonprod`, DNS name in the private zone | The load balancer controller and ExternalDNS in wl-nonprod, from the Ingress | wl-nonprod |
| Dex client `argo-workflows` (client entry in Dex's configuration) | Terraform, `addons-mgmt` [`sso.tf`](https://github.com/mlqube/infrastructure/blob/main/live/platform/addons/mgmt/sso.tf) | mgmt (Dex) |
| The client secret: Secrets Manager `mlqube/platform/argo-workflows/sso` | Terraform, same file, new random value on every build | AWS |
| Secret `argo/argo-workflows-sso` | External Secrets, from an ExternalSecret in `platform/argo-workflows/` (ApplicationSet `argo-workflows-config`) | wl-nonprod |
| A workflow ServiceAccount and RBAC per tenant namespace | The tenant setup ([golden path v0 plan](../../golden-path-v0-plan.md) section 2), not this add-on | Tenant namespaces |

No AWS permissions for the controller or the server. A workflow gets its tenant's AWS role through its own ServiceAccount (Pod Identity, section 2).

## Signing in

| Who | How | Mode |
|---|---|---|
| **People** | Single sign-on through [Dex](dex.md) and IAM Identity Center, like Argo CD | `sso` |
| **CI** (the project's GitHub Actions) | The token of a ServiceAccount in the project's namespace that may only submit and watch workflows there; read from Secrets Manager with CI's OIDC role, sent over Tailscale | `client` |

The client secret path differs from Argo CD's because Argo Workflows runs in wl-nonprod, where the `addons-mgmt` Terraform layer has no Kubernetes access: Terraform writes the secret to Secrets Manager, External Secrets in wl-nonprod copies it into the `argo` namespace. Both sides (Dex's config and the Secret) get the same new value on every build.

**v0 limitation:** `sso.rbac` is off, so everyone who signs in uses the Argo server's own permissions (all workflows). Who can sign in at all is decided in IAM Identity Center: only people assigned to the application (today, the platform admins). Per-tenant access (a tenant's group ID → a ServiceAccount in its namespaces) comes with the tenants, generated by the glue ([the MlQube glue](../../glue.md)).

## Settings

| Setting | Value | Why |
|---|---|---|
| Chart | `argo-helm/argo-workflows` **2.0.18** (Argo Workflows v4.1.6, released 2026-11-06) | At least two weeks old when chosen |
| CRDs | Installed by the chart, minified (`crds.full: false`), applied server-side, kept on uninstall | The full CRDs come through a Helm hook Job: one more moving part, no benefit here |
| Workflow defaults | Finished workflows removed after 3 days (`ttlStrategy`); successful pods deleted at once, failed pods kept with their logs until the workflow goes (`podGC: OnPodSuccess`) | The golden path's retention ([ADR-0016](../../adr/0016-golden-path-v0.md)) |
| Workflow RBAC in `default` | Not created (`workflow.rbac.create: false`, `workflowNamespaces: []`) | Workflows run only in tenant namespaces, which bring their own |
| Workflow archive | Off in v0 | Needs PostgreSQL; added with the in-cluster databases (section 4) |
| Server | `secure: false` (TLS ends at the ALB), auth modes `sso` and `client` | [ADR-0010](../../adr/0010-ingress.md) |
| Replicas | 1 controller, 1 server | Reference build; two each in production |

## Checking it (build A)

```bash
kubectl --context wl-nonprod -n argo get pods,ingress
kubectl --context wl-nonprod -n argo get externalsecret,secret argo-workflows-sso
curl -sI https://workflows.nonprod.mlqube.click   # over Tailscale: 200
```

- [ ] UI at `https://workflows.nonprod.mlqube.click` signs in through Identity Center
- [ ] A test workflow (see [Kueue: testing it](kueue.md#testing-it-build-a)) runs a GPU step and is removed 3 days later
- [ ] The server's log shows no SSO errors: `kubectl --context wl-nonprod -n argo logs deploy/argo-workflows-server --tail=50`

| Symptom | Likely cause | Check |
|---|---|---|
| Server pod crash-loops: secret `argo-workflows-sso` not found | External Secrets hasn't synced yet, or Terraform didn't write the secret | `kubectl -n argo describe externalsecret argo-workflows-sso`; `aws secretsmanager describe-secret --secret-id mlqube/platform/argo-workflows/sso` |
| Sign-in ends with `invalid_client` or a redirect error at Dex | Dex still runs with an older config (it reads it at start) | `kubectl --context mgmt -n dex rollout restart deployment/dex` |
| Sign-in can't reach Dex from the server | Dex's ALB allows only the VPC ranges; wl-nonprod's range must be in `inbound-cidrs` (it is: 10.20.0.0/16) | `kubectl --context wl-nonprod -n argo exec deploy/argo-workflows-server -- wget -qO- https://dex.mlqube.click/.well-known/openid-configuration` |
